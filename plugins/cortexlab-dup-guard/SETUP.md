# CortexLab Dup Guard — セットアップ & 使い方ガイド

CortexLabの共同開発で、**同じ機能を別々に作ってしまう手戻り**を防ぐための
Claude Codeプラグインです。バックログ登録や開発着手の**前**に、Linearの
バックログとGitHubのブランチ/PRを自動で横断チェックし、重複・類似があれば
アラートを出します。

このファイル1枚で、導入から普段の使い方まで分かるようにまとめてあります。

---

## これは何をしてくれるのか

- これから登録するバックログと**同じ/似たIssueがLinearに無いか**
- これから作る機能が**既に別ブランチ/PRで実装されていないか**
- 似たIssueの**ステータスと担当者**(相方が既に進めていないか)

を調べて、次の3段階でアラートします。

- 🔴 **重複あり** — 同一機能のIssueか実装ブランチが既にある
- 🟡 **類似あり・要確認** — 近い機能や同じモジュールを触る作業が進行中
- 🟢 **重複なし** — 新規で進めてOK

さらに、うっかり防止として **Linearへのissue作成を「重複チェック済み」に
なるまで自動でブロック**します(あとで詳述)。

---

## 事前に必要なもの

- **Claude Code** が使えること(あなたのアカウントで `claude` が起動できる)
- **git** が入っていて、CortexLabのリポジトリを `git clone` 済みで、普段
  `git push/pull` できていること(GitHubの認証が通っている状態)
- Linearのアカウント(CortexLabのワークスペースに入っていること)

> `gh` CLI や GitHub MCP は**任意**です。あればPR情報も見ますが、無くても
> ブランチ検索は動きます。

---

## セットアップ(各自の環境で1回ずつ)

あなたと相方、**それぞれの環境で**以下を実施してください。トークンなどを
共有する必要はありません(各自のアカウントで認証します)。

### 手順1. Linear MCP を接続する

Claude Code に Linear をつなぎます。ターミナルで:

```bash
claude mcp add --transport http linear https://mcp.linear.app/mcp
```

- 初回はブラウザが開いて **LinearのOAuth認証**が走ります。承認してください。
- 接続できたか確認:

  ```bash
  claude mcp list
  ```

  一覧に `linear` が出ていればOKです。

> **スコープの注意**: 上のコマンドは実行したプロジェクトに紐づきます。
> 全プロジェクトで使いたいなら `--scope user` を付けてください。
> CortexLab専用でよければ、CortexLabのリポジトリ内で実行するのがおすすめです。

### 手順2. プラグインをインストールする

プラグインのマーケットプレイスを追加して、インストールします。

```
/plugin marketplace add umiji/Hawkeye-Re
/plugin install cortexlab-dup-guard@cortexlab-tools
```

> - スラッシュコマンドは、ターミナルではなく **Claude Code のセッション内**で
>   打ちます。
> - `/plugin marketplace add` はデフォルトブランチを読みます。まだmainに
>   マージ前の場合は、リポジトリをローカルにcloneして
>   `/plugin marketplace add /path/to/repo` でローカル追加してください。
> - CortexLab本体のリポジトリにプラグインを移設した場合は、`umiji/Hawkeye-Re`
>   の部分をそのリポジトリ(`<owner>/<repo>`)に置き換えてください。

### 手順3. 動作確認

CortexLabのリポジトリ内でClaude Codeを起動し、次を実行:

```
/cortexlab-dup-guard:dup-check 動作確認用のダミー機能
```

Linearとブランチを検索したレポート(🔴/🟡/🟢)が返ってくれば成功です。

## 普段の使い方

いつも **CortexLabのリポジトリ内でClaude Codeを起動**してから使ってください
(見るブランチ = 起動したリポジトリ、のため)。

### A. バックログを登録するとき → `/backlog-add`

```
/cortexlab-dup-guard:backlog-add 通知機能のメール送信対応
```

1. Linearの類似Issue・GitHubの類似ブランチを検索してレポート
2. 🟢なら、そのままLinearにIssueを登録(類似Issueがあれば説明文に「関連」
   としてリンク)
3. 🟡/🔴なら、重複相手を見せたうえで「登録する/既存に合流する/やめる」を確認

> 💡 コマンドを使わず「これLinearに登録して」と普通に頼んだ場合でも、
> 後述のガードがチェックを強制するので、うっかり重複登録を防げます。

### B. 開発に着手するとき → `/start-task`

```
/cortexlab-dup-guard:start-task CTX-42
```

(Issue IDでも、機能の説明文でもOK)

1. そのIssueの内容で類似検索。特に **In Progress の類似Issueと担当者**、
   **既存ブランチの実装**を重点チェック
2. 「着手OK」/「◯◯さんが類似Issueを進行中 → 分担相談」/「既存ブランチに
   実装済みの可能性 → まず中身確認」を判定
3. 問題なければ、そのIssueを**自分にアサイン + In Progress化**し、Issue IDを
   含むブランチ名(例 `feat/CTX-42-email-notify`)を提案

### C. とりあえず重複だけ確認したいとき → `/dup-check`

```
/cortexlab-dup-guard:dup-check 検索のインクリメンタル化
```

チェックとレポートのみ(Issue登録はしません)。

---

## 自動ガードについて(重要)

「チェックを忘れて登録してしまう」を防ぐため、**Linearのissue作成操作を
機械的にブロック**する仕組みが入っています。

- Linear MCPでissueを作ろうとしたとき、**直近45分以内にこのプロジェクトで
  重複チェックが記録されていない**と、作成が**拒否**されます。
- 拒否されると、先に重複チェック(`/backlog-add` や `/dup-check`)を通すよう
  案内が出ます。チェックを通せば45分間は作成できるようになります。
- チェックを実際に行ったときだけ記録される規約なので、「チェックせず記録だけ」
  はできません。

### 一時的に無効化したいとき

急ぎでガードを外したい場合は、Claude Code起動時に環境変数を付けます:

```bash
DUP_GUARD_DISABLE=1 claude
```

---

## うまくチェックさせるためのコツ

このツールは **GitHubにpush済みのブランチ** と **Linearの登録済みIssue** しか
見られません(gitの原理上、未pushのローカルブランチは誰にも見えません)。
精度を上げるために、二人で以下を習慣にすると効果的です。

- **着手したらLinearでIn Progressにする**(`/start-task` が自動でやります)
  → まだpushしていなくても「誰が何を進行中か」が相方に見える
- **早めにpushする**(WIPでもよい) → GitHub側の実装検知が効く
- **ブランチ名にIssue IDを入れる**(`feat/CTX-42-...`) → ブランチとIssueの
  突き合わせ精度が上がる
- 二人が**同じGitHubリポジトリ**にpushしていること(fork運用だと相手のforkは
  見えないので、その場合は要相談)

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| レポートに「Linear MCP未接続」と出る | 手順1をやり直し。`claude mcp list` で `linear` を確認 |
| `/cortexlab-dup-guard:...` が候補に出ない | `/plugin` でインストール状態を確認。手順2を再実行 |
| ブランチが検索されない | CortexLabのリポジトリ**内**でClaude Codeを起動しているか確認 |
| 「fetch失敗」と注記される | `git fetch` が通るか(認証・ネットワーク)を確認 |
| Linear作成がブロックされる | 仕様どおり。先に `/dup-check` か `/backlog-add` を通す |
| フックが自分のLinearツールに反応しない | サーバー名を変えて登録している場合、`hooks/hooks.json` の matcher を調整 |

---

## しくみ(念のため)

- チェック担当は **duplicate-detector** というサブエージェント。**読み取り
  専用**で、Issueの作成・更新はしません(登録はコマンド側の明示フローだけ)。
- ブランチ調査は `git fetch --prune` → `git branch -r` / `git log` / `git diff`。
  **作業ツリー(フォルダのファイル)は変更しません**。fetchはリモート情報を
  読み込むだけです。
- 「チェックしてから登録」はお願いベースではなく、**フックで機械的に強制**
  しています。
- 確認できなかった情報源(Linear未接続、権限不足、fetch失敗など)は、勝手に
  「重複なし」とはせず、レポートに「未確認」と明記します。
