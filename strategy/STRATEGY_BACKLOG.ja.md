## 1. 総合判定(要約)

「投資の神」として年率50%必達の観点で現行設計を監査した結論:

**「バイアス排除の実験室」としては一級品の設計。「50%必達の兵器」としては、
弾倉(試行回数)・照準の先(利益の伸ばし方)・装薬量(リスク量)の3つが未装着。**
そして防御(ドローダウン回路遮断・地合いフィルタ・セクター上限)を欠いたまま
装薬だけ増やすと今度は破裂する。

理由は次章の算数で示す通り、現行パラメータのままフル稼働できたとしても
理論上限が目標ぎりぎりであり、実際の稼働率(見送りの多さ・決算閑散期)を
織り込むと年率15%前後にしかならない可能性が高い。

## 2. 算数から見た現状

前提を明示した上での概算(検証可能にするため計算過程を残す。実際の勝率・
実現Rは未知数であり、Phase 0のデータが出るまで確定しない)。

### 2.1 理論上限(かなり楽観的な仮定)

| 項目 | 値 | 根拠 |
|---|---|---|
| 1回のリスク量(1R) | NAVの0.75% | `config.py: default_risk_pct` |
| 想定的中率 p | 55% | 楽観的だが非現実的ではない水準 |
| 勝ちペイオフ | +2R | `config.py: min_reward_risk`(最低ライン) |
| 負けペイオフ | -1R | ストップ執行を仮定 |
| 1回あたり期待値 | 0.65R = NAVの0.4875% | 0.55×2 − 0.45×1 = 0.65R |
| 年間トレード数 | 約97回 | 8枠フル稼働 × 365/30日保有 |
| **単純合算(非複利)** | **約+47%** | 97 × 0.4875% |

→ **フル稼働・的中率55%・毎回きっちり2R以上で決着**という、かなり都合の良い
前提を置いて初めて目標圏内。複利を加味すればもう少し高くなるが、逆に言うと
**この仮定から外れる方向にしか動かない**。

### 2.2 現実的な見積もり

| 項目 | 値 | 根拠 |
|---|---|---|
| 稼働率 | 約7割 | 決算閑散期・厳格な見送り基準による打席減 |
| 平均実現R | 約1.3R | 目標到達=即レビュー(利伸ばし機構が無い)ため、+2R到達前に決済されるケースが混入 |
| 年間トレード数 | 約68回 | 97 × 0.7 |
| 1回あたり期待値 | 0.265R = NAVの0.199% | 0.55×1.3 − 0.45×1 |
| **年間(単純合算)** | **約+13.5%** | 68 × 0.199% |

**現行設計のままでは、エッジが仮説通り実在したとしても年率15%前後が現実的な
着地点**という試算になる。50%との差は「エッジが弱い」からではなく、
「試行回数・利益の伸ばし方・リスク量の3つのレバーが未接続」だからである。

### 2.3 参考: Kelly基準との比較(リスク量を上げる余地の確認)

同じ前提(p=0.55、payout 2:1)でのフルKelly比率:

```
f* = p − q/b = 0.55 − 0.45/2 = 0.325  → NAVの32.5%
```

現行の0.75%はフルKelly比の約1/43(2.3%)に相当し、保守的なファンドの基準
(1/4〜1/10 Kelly)と比べても極めて臆病な水準。仮に1.5%へ引き上げても
1/22 Kelly、2.5%でも1/13 Kelly——「上げても壊れない余地」は数学上ある。
ただし**pとpayoutは未知数であり、この計算はPhase 0の実データが出るまで
確定しない**。だからこそ「今すぐ上げる」のではなく「条件を先に決めておく」
(バックログ BL-02)が正しい順序になる。

## 3. 指摘事項の詳細

### 3.1 攻め(試行回数・右テール・リスク量) — 目標達成に直接効くレバー

**① 検知器の多様化不足**
候補発掘が決算サプライズのみのため、決算閑散期は候補ゼロになる。「カタリスト
が無ければ休む」という規律自体は正しいが、50%必達には年間80〜120回規模の
質の高い打席が要る。インサイダー買い集中・優良銘柄の過剰反応(逆張り)・
指数採用/スピンオフ・ガイダンス修正など、互いに相関の低い検知器が複数要る。
→ バックログ **BL-10**(ROADMAP上は既にPhase 2に位置づけ済み。優先順位は
そのまま据え置く)

**② 利益の右テールを自ら切り捨てている**
現在「目標到達」はレビューシグナルであり、実質的に+2R前後で利確される設計。
カタリスト投資の年間成績は、年2〜3回出る大化け(+30〜50%)を取り切れるかで
ほぼ決まる。目標到達時に「半分利確+残り半分はストップを切り上げながら伸ばす」
仕組みに変えることが、費用対効果最大の一手。
→ バックログ **BL-12**(ただしOutcome/PositionPlanのモデル変更を伴う中〜大
規模の設計変更。現時点で保有ポジションが0件のため、実装の緊急性は無い)

**③ リスク量拡大の条件が未定義**
0.75%は臆病すぎる可能性が高い(2.2参照)一方、「いつ上げるか」を今のうちに
機械的な基準として決めておかないと、後から都合よく決めてしまう
(=このシステムが排除したいはずの自己奉仕バイアスの再発)。
→ バックログ **BL-02**

**⑦ 情報エッジの本命が後回し**
現在の入力(見出し+要約+機械計算サプライズ)は誰でも持っている情報で、
そこに優位性は無い。セッションモードで限界費用がほぼゼロになった「大量の
一次資料の深読み」(決算説明会の質疑応答の温度感、10-Qの脚注、ガイダンス
文言の四半期比較)こそが、AIならではの情報優位の本命。
→ バックログ **BL-11**(Phase 2の中でも最優先候補)

**⑧ 逆選択リスク(シナリオの盛り癖)**
期待値ハードル(+5%)を課すこと自体が、「特別な案件」だけでなく「シナリオを
強気に盛った案件」も通してしまうリスクがある。Brierスコアはいずれ検出するが、
発生から検出までのタイムラグを縮めるため、Bullの基本シナリオと実現値の乖離を
明示的に監視すべき。
→ バックログ **BL-03**

### 3.2 守り(ドローダウン・レジーム・集中) — 大負けを防ぐレバー

**④ ポートフォリオ全体のキルスイッチが無い**
個別ポジションのキル基準はあるが、帳簿全体のドローダウン管理が未定義。8枠が
同時逆行すれば一撃で約-6%、連敗が重なれば-15%も普通に起こり得る。-33%の
損失は+50%で取り返す必要があり、**1回の大きなドローダウンで1年分の目標が
消える**。ピークNAVからの下落率に応じて新規リスクを段階的に絞る回路遮断器が
必要。
→ バックログ **BL-07(基盤)→ BL-08(本体)**

**⑤ 地合い(レジーム)フィルタが無い**
ロング専用のカタリスト戦略は下落相場で的中率・値幅とも劣化しやすい。
「S&P500が200日移動平均を下回っている間は新規リスクを半減」程度の単純な
フィルタで複利の分母を守れる。
→ バックログ **BL-09**

**⑥ セクター集中の制御が無い**
現在の制約は「最大8銘柄・1銘柄10%まで」のみ。決算シーズンは同一セクターの
好決算が固まって出るため、8枠が事実上「特定セクター1本賭け」になり得る。
→ バックログ **BL-06**

### 3.3 戦術(執行品質) — 小さいが積もると効く

| 項目 | 問題 | バックログ |
|---|---|---|
| エントリー価格の鮮度ルールが無い | 提案時参考価格から乖離した価格で約定すると期待値の大半が消える | **BL-04** |
| 損切りラインの品質がLLM任せ | Bullが書くストップ位置の根拠が案件ごとにばらつく | **BL-05** |
| 事後検証に市場との比較が無い | BUY群がPASS群に勝っても両方が市場に負けていたら無意味 | **BL-01** |

## 5. 実装順序の考え方(なぜこの並びか)

1. **Tier A(1〜4)を最初に置く理由**: どれも「計測を増やす」か「警告を足す」
   だけで、既存のゲート判定・裁定ロジックには一切触れない。Phase 0の
   BUY/PASS比較統計を一切汚さず、むしろ精度を上げる。着手するのに理由が
   要らない。
2. **Tier B(5〜6)を次に置く理由**: リスク管理役の判定ロジックに小さな変更
   が入るため、本来は「変更前後でコホート統計を分けて見る」規律が要る
   (`ROADMAP.md` のPhase 1運用ルールと同じ考え方)。しかし**現時点で評価
   済み候補がわずか3件しかなく、コホートの前後分割コストが実質ゼロに近い**。
   後から(30件・50件貯まった後で)同じ変更をすると、その時点で統計の
   連続性が壊れてしまう。**「サンプルが少ない今」が最安のタイミング**であり、
   先送りするほど高くつく。
3. **Tier B2(7〜9)を次に置く理由**: ドローダウン回路遮断器(BL-08)は
   NAV追跡(BL-07)という基盤が無いと作れない。地合いフィルタ(BL-09)は
   独立に着手可能だが、守り系としてまとめて扱う。いずれも判定ロジック本体
   (ゲート・審理・サイジング)には触れず、「新規リスクを絞る」外側の
   ブレーキなので、Phase 0の中核統計への影響は小さい。
4. **Tier C(10〜11)を待たせる理由**: `ROADMAP.md` に既に事前登録されている
   Phase 0のキル基準(評価50件時点でBUY群がPASS群に勝てずBrier≥0.25なら
   自動化に投資せず再設計)を尊重する。検知器を増やす・一次資料を読み込む
   投資は、いまの少ない検知器だけでエッジの片鱗があるかを確認してから
   でないと、悪い入口を増やすだけになりかねない。**この判断は今回の監査で
   変更しない**——「攻めのレバーが足りない」という指摘と、「検証が先」
   という既存の規律は矛盾しない。前者は「Phase 0合格後に何をするか」の
   優先順位付けであり、後者は「Phase 0合格前に何をしないか」の話。
5. **Tier D(12)を最後に置く理由**: 利益の伸ばし方の再設計は効果が最大級
   である一方、`Outcome`・`PositionPlan` のデータモデル変更を伴う。かつ
   **現時点で保有ポジションが0件**のため、実装しても適用対象が無い。
   設計(部分利確をどう記録するか、トレイリング幅の決め方)は今のうちに
   詰めておき、実装は最初のBUYポジションが目標に近づくタイミングまでに
   間に合わせれば十分。

## 6. 次のアクション

このバックログのうち、どこまでを実装フェーズに進めるか判断をお願いします。

- **提案**: Tier A(BL-01〜04)は計測改善のみでリスクが無いため、一括承認
  いただければすぐ着手します。
- Tier B(BL-05〜06)も、サンプルが増える前の「今が最安」の論理に納得
  いただければ、Tier Aと同時に着手可能です。
- Tier B2(BL-07〜09)は中規模の実装なので、別途スコープ確認の上で着手します。
- Tier C(BL-10〜11)は既存のROADMAPキル基準判定を待ちます(変更不要)。
- Tier D(BL-12)は設計メモの作成のみを今回のスコープとし、実装は保留します。
