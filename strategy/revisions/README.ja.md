# 改訂案(revisions)

落選候補のレビュー(`/hawkeye-review`)が、**同じ原因の見落としが20件たまった
分類**について起草した「絞り込みロジックをこう変えてはどうか」という提案を
ここに置きます。ファイル名は `YYYY-MM-DD-<分類>.ja.md`。

## ここにあるものは「提案」であって「決定」ではない

起草するのはAgentですが、**採否を決めるのは人です。** 承認したら、その改訂を
実際のコード(数値なら `hawkeye/config.py`、条件なら該当モジュール)に反映し、
コミットメッセージからこのファイルを参照してください。不変条件7が「ルール変更は
根拠つきの設定差分である」ことを求めているので、**このファイルがその根拠**に
なります。

却下した場合もファイルは消さずに残します。「なぜ変えなかったのか」は、
半年後に同じ提案が再び出てきたときに一番効く記録だからです。

## なぜ `docs/` ではなく `strategy/` なのか

`docs/` はシステムの設計文書、`strategy/` は投資判断の基準です。改訂案は
「候補の絞り込み方をどう変えるか」という**投資判断の基準側**の話なので、
こちらに入ります。また、システムが吐いた生データ(`var/`)とは違い、
**人が承認する対象**なのでGit管理します。
