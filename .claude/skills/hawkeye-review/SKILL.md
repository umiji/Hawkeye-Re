# Hawkeye review — 落選候補レビュー1巡

あなたはこのセッションで **落選候補レビュー** を回します。`/hawkeye-run`
(毎日の候補選定)とは別のセッションで動かす前提です。理由は2つ:
このレビューは過去分をまとめて読むためトークンを大きく使うこと、そして
日々の候補選定を止めずに独立して回せること。

ユーザーとの会話はすべて日本語です。

## この作業が何のためにあるか

Hawkeyeは毎回たくさんの銘柄を落としています(ゲート不合格・ランキング下位・
肉付け上限)。**落としたまま誰も答え合わせをしないと、絞り込みのルールが
間違っていても永久に気づけません。** この巡回は落とした銘柄のその後の値動きを
測り、大きく外れたものだけを1件ずつ調べ、**同じ原因が20件たまった時にだけ**
ルール改訂案を起草します。

用語(初出のみ):
- **α(アルファ)**: 実際のリターンから「市場全体が動いた分」を差し引いた残り。
  相場が良かっただけなのか、その銘柄固有の動きだったのかを分けるための物差し。
- **z**: αを「その銘柄自身の普段の値幅」で割った倍率。値動きの荒い小型株と
  大型株を同じ土俵で比べるために使います。**|z| ≥ 1.5 を外れ値**とします。
- **miss_category(分類)**: なぜ外したのかの原因コード。件数を数える単位です。

## 守ること(破るとレビューが自己欺瞞になります)

1. **調査サブエージェントは1銘柄につき1つ、必ず新規で起動する。**
   前の銘柄の印象を次に持ち込ませないためです。
2. **`hawkeye drops queue --case-id` が出力したものだけを渡す。**
   判断日より後に公開された記事はCLI側で機械的に除外済みです。あなたが
   別途ニュースを取ってきて渡してはいけません — それをやると除外が無意味に
   なります。
3. **サブエージェントにツールを使わせない。** 渡した資料だけで答えさせます。
   Web検索を許すと、判断日より後の情報が必ず混ざります。
4. **あなた自身が調査結果を書かない。** サブエージェントのJSONをそのまま
   ファイルに保存し、`hawkeye drops submit` に渡します。
5. **改訂案を勝手にコード反映しない。** `strategy/revisions/` にファイルとして
   保存し、採否はユーザーが決めます。

## 手順

### 0. 準備

```bash
cd <repo>
export PATH="$PWD/.venv/Scripts:$PATH"   # Windows。macOS/Linuxは .venv/bin
hawkeye drops queue                       # 前回の中断が残っていないか確認
```

調査待ちが残っていた場合は、**測定から始めずステップ2から**再開してください。

### 1. 測定(T+5 → T+10 の順)

```bash
hawkeye drops measure --checkpoint t5 --reviewer claude-code-session
hawkeye drops measure --checkpoint t10 --reviewer claude-code-session
```

- **T+5は測って記録するだけ**で、個別調査はしません。同じ銘柄をT+5とT+10の
  両方で調べると、20件の集計に二重計上されるためです。
- **T+10で |z| ≥ 1.5 だったものだけ**が調査待ちに積まれます。
- 記録済みの銘柄は自動的に対象外になります(測り直しはできません)。

### 2. 個別調査(調査待ちがある場合のみ)

```bash
hawkeye drops queue          # 待ち行列を表示
```

1件ずつ、次を繰り返します:

```bash
hawkeye drops queue --case-id <case_id>    # 調査用の資料を出力
```

出力された資料を**そのまま**新しいサブエージェント(Task/Agent)に渡します。
サブエージェントへの指示は次の通り:

> あなたは投資判断の事後検証を行う調査役です。以下の資料だけを読み、
> ツールは一切使わずに答えてください。資料には「①判断時点で我々の記録に
> あった材料」「②判断日までに公開されていた記事」が含まれます。
> **判断日より後の情報は意図的に除外されています。**
> 次のJSONだけを返してください(前後に説明文を付けない):
>
> ```json
> {
>   "what_happened": "何が起きたか",
>   "visible_evidence": ["判断時点の記録から引用できる根拠", "..."],
>   "miss_category": "gate_threshold_too_strict | score_formula_wrong | enrichment_cap | data_gap | collection_gap | unforeseeable | gate_correct | other",
>   "notes": "otherの場合は必須",
>   "evidence_urls": ["..."],
>   "proposed_change": {"target": "変える対象", "direction": "どちらへ", "rationale": "理由"},
>   "confidence": 0.0
> }
> ```
>
> 分類の判断基準:
> - `unforeseeable` は「値動きを起こした情報が**判断日より後**に発生・公開
>   された」場合**のみ**。
> - 「判断日より**前**に公開されていたのに我々の記録に無かった」なら
>   `collection_gap`。
> - **迷ったら `collection_gap`**。「予見不能」は改善のしようがない分類なので、
>   そこに逃げ込むと直せる欠陥が永久に隠れます。

返ってきたJSONをファイルに保存し、投稿します:

```bash
hawkeye drops submit <case_id> --file <保存したJSON>
```

`unforeseeable` と答えても、判断日前に公開されていた未収集の記事がある場合は
**CLIが自動的に `collection_gap` に訂正**し、その旨を備考に残します。これは
仕様であって不具合ではありません。

すべての調査待ちが無くなるまで繰り返します。

### 3. 報告と改訂判定

```bash
hawkeye drops revise
```

**このレポートは20件に達していなくても毎回出ます。** 出力をそのまま
ユーザーに提示してください。含まれるもの:

- 今回測った件数・段階別の内訳・累計と前回からの増分
- 外れ値(上振れ・下振れ両方。ゼロなら「該当なし」— これは正常な結果です)
- 個別に調べた銘柄ごとの要約(何が起きたか / 判断時点の根拠の引用 / 分類)
- 分類ごとの累計と、20件までの残り件数
- 測定できなかった件数とその理由(生存者バイアスの注意つき)

### 4. 改訂案の起草(20件に到達した分類がある場合のみ)

到達分類が報告された場合のみ、**分類1つにつきサブエージェントを1つ**起動して
改訂案を起草させます。渡す材料:

```bash
hawkeye drops report --checkpoint t10      # 段階別・ゲート別の集計
```
に加えて、その分類の全レビュー行(`hawkeye drops revise` の出力から)。

起草した改訂案を `strategy/revisions/YYYY-MM-DD-<分類>.ja.md` に保存し、
内容を画面にも表示します。書式:

```markdown
# 改訂案: <分類の日本語名>(<category key>)

## 根拠となった観測
- 該当件数 / 対象銘柄 / 共通していた事実

## 提案する変更
- 対象(`hawkeye/config.py` のどの値か、あるいはどのロジックか)
- 変更の方向と幅
- この変更で**過去の何件が救われ、代わりに何件が新たに通ってしまうか**

## 反証(この変更をすべきでない理由)
- 過剰最適化になっていないか。20件は同じ原因だと本当に言えるか

## 未解決
```

**必ず反証の節を書かせてください。** 改訂案が「変えるべき理由」だけを並べた
文書になると、レビューは緩める方向にしか動きません。

保存後、ユーザーに次を伝えます:「採否はユーザーが決めます。承認する場合は
`hawkeye/config.py` を変更し、コミットメッセージからこのファイルを参照して
ください(不変条件7)。却下する場合もファイルは残してください — なぜ変え
なかったかの記録が、半年後に同じ提案が出たとき一番効きます。」

## 途中で止まったとき

巡回の状態は `var/drops/` に残ります。調査待ちのケースファイルも、測定済みで
未報告の集計も、次のセッションでそのまま続きから再開できます。**`var/drops/`
を手で消さないでください** — 測定値は再現できません(βは過去250営業日の
回帰で求めるため、後日測り直すと別の数字になります)。
