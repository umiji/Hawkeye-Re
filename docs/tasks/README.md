# タスク台帳の構成（2026-08-17〜）

進捗管理の唯一の正本（single source of truth）は2つのファイル群に分かれている:

- **`docs/task-list-hawkeye-re.csv`**: 一覧（索引）。ID・作成日・更新日・
  タスク名・状態・依存タスク・ドキュメント（対応する個別ファイルへの
  相対パス）の7列のみ。セッションが「今どのタスクがどの状態か」を軽量に
  把握するためのファイルで、完了済みタスクの詳細や証拠は載せない。
- **`docs/tasks/T-XXX.md`**（このディレクトリ）: タスク1件ごとの詳細
  ファイル。目的・変更範囲・禁止事項・完了条件・テスト方法・停止条件・
  進捗・証拠をここに書く。着手中のタスク1件だけを読めば済むように、
  他タスクの詳細は同じファイルに混ぜない。

新規タスクの受付・登録手順は`hawkeye-task-cycle` Skill
（`.claude/skills/hawkeye-task-cycle/SKILL.md`）と`docs/task-template.md`
を参照。1タスクずつ進行し、完了条件を満たすまで次のタスクに着手しない。

## ID 採番ルール

- 形式は `T-###`（3桁ゼロ埋め、連番）。
- 一度発行した ID は再利用しない。中止・保留になったタスクもCSVの行を
  欠番のまま残し、削除しない（詳細ファイルも同様に残す）。

## CSV 列の使い分け

- **作成日 / 更新日**: `YYYY-MM-DD`。記録が残っておらず正確な日付が
  無い場合は「不明」と明記し、空欄や`-`のままにしない。
- **タスク名**: 10〜40文字程度。そのタスクを端的に説明したものにする
  （`docs/task-template.md` 項目1）。
- **依存タスク**: 他タスクへの依存（`docs/task-template.md` 項目8）。
  `T-001（ブロッカー）`/`T-001（推奨）`の短縮書式で書き、詳しい理由は
  対応する`docs/tasks/T-XXX.md`のメタデータ欄に全文を書く。依存が無け
  れば「無し」と明記し、`-`や空欄のままにしない。
- **ドキュメント**: 対応する個別ファイルへのリポジトリルート相対パス
  （例: `docs/tasks/T-001.md`）。文字列そのものはハイパーリンクには
  ならないが、正確な相対パスにしておけばエディタのファイル検索や
  セッションの読み込みでそのまま辿れる。

## 状態の選択肢

`未着手` / `調査中` / `実装中` / `ローカル検証済み` / `実環境検証待ち` /
`完了` / `保留` / `中止`

## 個別ファイルの構成（`docs/tasks/T-XXX.md`）

```markdown
# T-XXX: タスク名

## メタデータ
- 作成日: ...
- 更新日: ...
- 状態: ...
- 進捗: ...
- 依存: ...（全文。理由込み）

## 目的
## 変更範囲
## 禁止事項
## 完了条件
## テスト方法
## 停止条件
## 証拠
```

T-000〜T-008は旧形式（1つのMarkdownテーブル）からの移行時、原文の意味を
変えないことを優先し、目的・変更範囲・禁止事項を「## タスク詳細」に、
完了条件・テスト方法・停止条件を「## 完了条件」にまとめたまま移した
（分割すると原文の言い回しを書き換えるリスクがあるため）。T-009以降の
新規タスクは、上記の分割済みテンプレートで書く。
