# T-011: 抜粋モデルをGemini 3.5 Flash Liteへ移行し失敗理由を記録

## 目的

毎日の走査は、決算を出した約30銘柄それぞれについて「なぜこの四半期はこの数字になったのか」を会社自身の発表文から抜き出し、審理3役（Bull / Adversary / Judge）が一過性の要因と事業の実力を区別する材料にしている。その抜き出しを担う安価なモデルが、現在 `gemini-2.5-flash` である。

2026-08-18にUserが確認したモデル別上限表によれば、`gemini-2.5-flash` の無料枠は**日次20リクエスト**。1銘柄1リクエストなので、**30銘柄のうち約10銘柄は構造的に上限超過で落ちる**。落ちた銘柄は「発表文から説明を取れなかった」状態で審理に回り、3役は一過性要因かどうかを判断できないまま賛否を述べることになる。移行先の `gemini-3.5-flash-lite` は日次500・分間15で、30銘柄が余裕をもって収まる。

同時に、失敗時にサーバーが返す説明文を現行コードが捨てている。2026-08-18の実測でこれが実害として現れた: 3.5 Flash Lite に現行のリクエスト形式で投げたところ `HTTP 400` が返ったが、記録されたのは `the extractor answered 400` のみで、原因（後述の `thinkingBudget` 廃止）は別途生のAPIを直接叩くまで特定できなかった。この状態のままでは、本番走査で抜き出しが落ちても原因が永久に分からない。

## 変更範囲

- `hawkeye/marketdata/gemini.py` — 既定モデルを `gemini-3.5-flash-lite` に変更。リクエスト形式を3.x系に合わせる（`thinkingConfig.thinkingBudget: 0` → `thinkingConfig.thinkingLevel: "minimal"`。2026-08-18実測で前者は `HTTP 400 INVALID_ARGUMENT`、後者は成功し思考トークン0）。分間15リクエスト上限に合わせた最小呼び出し間隔（4秒）を追加。`GeminiUnavailable` にサーバーの説明文を載せる。
- `hawkeye/scout/cause_source.py` — `CauseText` に診断用の詳細欄を追加し、`text_for` が握り潰している例外の内容を名前付き理由と併せて運ぶ。
- 上記の詳細欄を表示する呼び出し側（`hawkeye/cli.py` の `cmd_cause_source`、および `hawkeye/scout/quality.py` / `hawkeye/scout/cause_agent.py` のうち理由を扱う箇所）。
- `tests/test_cause_release_source.py` / `tests/test_cause_source.py` — 間隔制御と詳細欄伝播のテストを追加。
- 文書の誤記訂正: `docs/design/CAUSE_SOURCE_EXTRACTION.ja.md`（§3.5）／`docs/tasks/T-008.md`（証拠欄）／`docs/knowledge/MEASUREMENTS.ja.md`。および `docs/design/DATA_SOURCES.md` のモデル行。
- `docs/task-list-hawkeye-re.csv` / 本ファイル。

## 禁止事項

- **逐語一致チェック（`build_cause_text`）の判定基準を緩めない。** モデルが変わって拒否ブロックが増えても、通すために許容範囲を広げるのは禁止。この機構だけがT-008の安全性（会社が言っていない文が会社の発言として審理に渡るのを防ぐ）を担保している。
- **引用チェックの照合先を抜粋に変えない。** 発表文全体のままとする。
- **リトライ回数・待機秒を推測で決めない。** 表の RPM 15 / RPD 500 から導出し、根拠をコード内コメントに書く。
- 2.5 Flash 向けの旧リクエスト形式を「念のため」二重に残さない。
- 誤記訂正では、誤っていた記述を消さずに「こう書いたが誤りだった」と残す。

## 完了条件

① **実行コマンド**: `.venv/Scripts/hawkeye.exe cause source AMBQ` → 3.5 Flash Lite 経由で成功し、`ベンダー要約: N文字 / 決算発表文: N文字 / 抜粋 N文字（発表文のN%）` 形式の出力が出て、抜粋文字数が0でないこと。

② **A/B測定（実データ30銘柄、記録済み基準との比較）**: T-008が測ったのと**同一の30銘柄**を `gemini-3.5-flash-lite` に通し、`docs/knowledge/MEASUREMENTS.ja.md` に記録済みの `gemini-2.5-flash` の実測値と突き合わせる。

   30銘柄は本番台帳（`var/hawkeye.db`）の決算実績テーブル（`earnings_prints`）で「情報源に理由が書かれていなかった」と記録された行（`cause_reason` が `no_cause_in_source`）として復元できることを2026-08-18に確認済み: AAON, ALCO, ALMR, HQI, PIII, QMCO, SDRL, SEPN, AII, AMBQ, EROC, STIM, DFDV, FOSL, HLIT, MSGE, STAA, AIRO, ARX, BFRI, BSP, ETON, FIGR, ISSC, LNSR, MSGS, NXPL, SGA, SPCB, TOMZ。

   **2.5 Flash 側を今日その場で測り直すことはできない** —— 2026-08-18時点でも日次20件の枠は消化済みで `HTTP 429` を返す（実測）。よって比較相手は記録済みの実測値とする:

   | 比較項目 | 2.5 Flash の記録値（2026-08-17） | 3.5 Flash Lite の合格基準 |
   |---|---|---|
   | 抜粋を作れた銘柄数 | 22 / 30（7件は上限、1件は理由なし） | **28 / 30 以上**（上限に当たらない分、増えるはず） |
   | 逐語一致率 | 79 / 81 = 97.5%（13銘柄での測定） | **90% 以上** |
   | 抜粋の総文字数 | 33,832（発表文の4.6%） | 発表文の **10%以下**（水増ししていないこと） |

   銘柄ごとに「返ってきたブロック数 / 逐語一致で通った数 / 拒否された数 / 抜粋文字数 / 失敗理由」を表で出す。拒否されたブロックは全文を残し、AII型の捏造かDFDV型の偽陽性かを1件ずつ確認する。下回った場合は切り替えを実施せず、停止条件に従ってUserへ報告する。

③ **実行コマンド（失敗時の診断可能性）**: 存在しないモデル名を指定して抜き出しを実行 → 記録される理由に `extractor_call_failed` だけでなく**サーバーが返した説明文が含まれる**こと。現状は `the extractor answered 400` しか残らない。
