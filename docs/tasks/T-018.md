- 依存: T-020（ブロッカー）

**依存の理由**: T-020 で「1件の決算が複数期の見通しを持てる」形に変わる。先に
この列を作ると、1期しか入らない前提の列を作った直後に作り直すことになる。
追加する6列のうち「対象期」は、まさにその複数期を表現する列である。

## 目的

### このファイルが最終的に何のためにあるか

`hawkeye report scan` は、その回の走査で何を見て何を審理に送り、他をなぜ落と
したかの報告を画面に出すと同時に、**全銘柄の表をCSVに書き出す**。画面の表は
読みやすさのために列と行を絞っているが、**CSVのほうは絞っていない**。

このファイルは、**Userが「今日の走査は本当に正しく動いていたか」を自分の目と
表計算ソフトで確かめるための唯一の全量データ**である。順位や採否を機械が
決めた根拠を、機械の言い分ではなく元の数字で検算するために存在する。

### 何が足りないか（その1: ガイダンスの実数値が無い）

CSVには「ガイダンス」という列が1つあるだけで、中身は「開示あり／開示なし」と
いう状態だけである（`_CSV_COLUMNS`、`hawkeye/reports/scan_report_ja.py:100`）。

```
| ガイダンス |
| 開示あり   |
```

EPS・売上については「実績/予想」と「サプライズ率」が全部入っているのに、
**見通しについては、会社が何と言ったのか・市場が何を期待していたのか・どちらが
上だったのかが、CSVから一切分からない。** 点数の内訳列（「ガイダンスで得た点」）
に結果だけが入るが、その点数がどの数字から出たのかは検算できない。

### 何が足りないか（その2: エラー列が3語しかない）

エラー列に入りうる値は次の3つだけである
（`hawkeye/reports/scan_report_ja.py:710-712`）。

| 表示 | 実際の意味 |
|---|---|
| 数値 | 決算専門サイト(EW)からEPS・売上の実績/予想が取れず、決算カレンダー(Finnhub)の数字で判定した |
| 見通し | 会社は見通しを述べているのに、こちらが読み取れなかった |
| 発表文 | 審理3役に渡す抜粋の一部が、却下されたか語句を改変された |

**「数値」という2文字から、上の説明にたどり着ける読み手はいない。** 2026-08-19
の走査でも EVGN と PONY の2行に「数値」とだけ出ており、Userから「これは何か」
という質問が実際に出た。

### 何が足りないか（その3: 比較の根拠として嘘の但し書きが出る）

会社見通しとコンセンサスを比べた結果には、「何と何を比べたか」を説明する
但し書きが添えられる。その文言は2つある
（`hawkeye/reports/quality_ja.py:145-146`）。

```python
"on_eps": "EPSレンジの中央値で比較",
"on_revenue": "売上レンジの中央値で比較(EPSレンジの開示が無いため)",
```

**括弧内の「EPSレンジの開示が無いため」は、EPSレンジが開示されていても付く。**
比較処理（`_guidance_leg`、`hawkeye/scout/quality.py`）は、EPSと売上の**両方**で
比べられたときに `on_eps` と `on_revenue` の両方を立てる仕様であり、そのとき
画面には矛盾した2行が並ぶ。

2026-08-19 の走査で AS に実際にこう出た。

```
  ガイダンス: ほぼ一致 -17.9%
    - EPSレンジの中央値で比較
    - 売上レンジの中央値で比較(EPSレンジの開示が無いため)
```

AS は EPS レンジ($0.31〜0.33)を開示している。1行目でEPSで比較したと言った
直後に、2行目でEPSの開示が無いと言っている。

### 放置した場合に困ること

- **検算ができない。** 見通しの点数がおかしいと感じても、CSVを見て確かめる
  手段が無く、台帳を直接SQLで開くしかない。それはUserの作業ではない。
- **T-020 で見つかったような取りこぼしを、Userが自力で発見できない。** AS の
  複数期ガイダンスの件は、発表文を人が読んで初めて分かった。会社見通しと
  コンセンサスが対象期つきでCSVに並んでいれば、表を眺めるだけで気づける。
- **エラー列が読めないため、その行を無視するか調べ直すかの判断がつかない。**
  「数値」は「決算カレンダーの数字で代用した（＝順位は付いているが出所が違う）」
  という意味であって、失敗を意味しない。今の表示はそれを伝えていない。

## 変更範囲

- `hawkeye/reports/scan_report_ja.py` の `_CSV_COLUMNS` と `_csv_cell` —
  ガイダンス6列の追加と、エラー列の文章化。
  - 追加する6列: EPSガイダンス（対象期／会社見通し／コンセンサス）、
    売上ガイダンス（対象期／会社見通し／コンセンサス）。
  - **対象期は1列に併記する**（User決定、2026-08-19）。書式は
    `2026-Q3（翌四半期）` / `FY2026（通期）`。生の期表記と分類を同じセルに入れる。
  - **エラー列は1文の説明文にする**（User決定、2026-08-19）。例:
    「決算専門サイトからEPSの数値が取れず、決算カレンダーの数字で判定しました」。
    複数該当する場合の連結方法は実装時に決め、理由を証拠欄に書く。
  - **会社見通しがレンジのときは、中央値だけをCSVに入れる**（User決定、
    2026-08-19）。$0.31〜0.33 なら `0.32`。表計算でそのまま割り算できることを
    優先する。レンジの上下は画面の表と台帳に残るため、失われはしない。
- `hawkeye/reports/quality_ja.py` — 比較の但し書き `on_revenue` の文言。
  「EPSレンジの開示が無いため」を無条件に付けるのをやめる。EPSでも比較できた
  ときと、売上でしか比較できなかったときとで、別の文言が出るようにする。
  どちらの状態かは既存のフラグ（`on_eps` が立っているか）で判別できるため、
  比較処理側を変える必要はない。
- `tests/` — 上記の単体テスト。

## 禁止事項

- **画面の表（`hawkeye report scan` が印字する Markdown 表）に列を足さない。**
  画面は読みやすさのために絞られており、それは意図された設計である。列の追加は
  CSVだけに行う。（但し書きの文言修正は別で、下の項を参照）
- **比較の但し書きは、文言だけを直す。** どちらの但し書きを出すかを決めている
  比較処理（`hawkeye/scout/quality.py` の `_guidance_leg`）のロジック、および
  `on_eps` / `on_revenue` というフラグの立ち方は変えない。壊れているのは
  日本語の文であって、判定ではない。
- **既存の列を削除・改名・並べ替えしない。** 追加と、エラー列の値の書き換え
  だけを行う。
- **CSVのファイル名に触らない。** それは T-019 の範囲。
- **既に別列にある詳細な理由（「取得できなかった理由」「見通しが読めなかった
  理由」）を消さない。** エラー列は要約であり、詳細列との重複は許容する。
- **点数・順位・ゲート判定のロジックに触らない。** これは表示だけのタスクである。
- **CSVの文字コード（BOM付きUTF-8）を変えない。** 日本語WindowsのExcelが
  文字化けするのを防ぐために付いている。
- **仕様が不明な点を推測で埋めない。**

## テスト方法

- **単体（オフライン）**: 6列の値の組み立て（開示あり／開示なし／複数期／
  EPSのみ開示／売上のみ開示）と、エラー列の文章化（3種すべて、および複数該当）、
  および比較の但し書き（`on_eps` と `on_revenue` の両方が立つ場合／`on_revenue`
  だけが立つ場合の2通り）。
- **回帰**: 既存全テスト。特にCSVの列数・列順を検証している既存テストがあれば、
  追加によって落ちるのは想定内なので期待値を更新する（このタスクでは列追加が
  仕様であるため、その1点に限り書き換えは正当）。
- **実環境確認**: 完了条件①〜⑥。実装者が既存の走査番号3に対して実施する。
