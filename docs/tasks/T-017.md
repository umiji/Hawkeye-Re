# T-017: 審理レポートのファイル名にティッカーを含める

## メタデータ

- 作成日: 2026-08-19
- 更新日: 2026-08-20
- 状態: 完了
- 進捗: 100%
- 依存: 無し

## 目的

### この処理が最終的に何のためにあるか

審理（強気役 Bull・反論役 Adversary・判定役 Judge の3役が1銘柄を争う工程）が
終わると、その結論と全やり取りを1件のMarkdown文書としてディスクに保存する
（`_write_tribunal_report`）。**Userが後日「この銘柄を、あのときなぜ買わなかった
のか／買ったのか」を読み返し、判断が正しかったかを検証するための唯一の読み物**
である。台帳（SQLite）にも記録は残るが、あれは機械が読む形式であり、Userが
開いて読むのはこのファイルのほうである。落選候補の見直し（`/hawkeye-review`）
でも、この文書が根拠テキストになる。

### 何が壊れているか

**保存先のファイル名が「年月日-時分秒」までしか使っておらず、銘柄名が入って
いない。** そのため同じ1秒間に2件の審理が終わると、後の1件が前の1件のファイルを
丸ごと上書きして消す。

```python
# hawkeye/cli.py:323-324
stamp = to_jst(datetime.now(timezone.utc)).strftime("%y%m%d-%H%M%S")
path = out_dir / f"{stamp}-tribunal-report.md"
```

### 実際に起きた（2026-08-19、走査番号3）

RNW と PONY の審理を続けて確定させたところ、両方が `00:52:06` に完了し、
両方の実行画面が同じ保存先を表示した。

```
(レポート保存先: var\reports\260819-005206-tribunal-report.md)
(レポート保存先: var\reports\260819-005206-tribunal-report.md)
```

残っていたのは PONY のほうだけで、**RNW の審理レポートは消えた**。

```
$ head -1 var/reports/260819-005206-tribunal-report.md
# ⚪ 見送り(PASS): PONY Pony AI Inc
```

### 放置した場合に困ること

Userが後から見送りの根拠を確認しようとしたとき、**その銘柄のファイルだけが
存在しない**。台帳に提案IDと結論は残るので誤発注には繋がらない（金銭判断その
ものは歪まない）が、**判断の追跡ができなくなる**。この仕組みは「あとから検証
できること」を前提に組まれており、検証材料が消えるのは目的そのものの毀損である。

さらに、**消えたことに気づく手段が無い**。上書きは静かに成功し、画面には
「保存先: ...」と正常に出る。今回も、同じパスが2回表示されたことに気づかなければ
発覚しなかった。

### 頻度

2026-08-19 の実測で3件中1件（33%）。ただしこれは審理を間を空けず連続で確定
させたときに起きるもので、1件ずつ手で実行する運用なら通常は衝突しない。
**標本は本日1回のみ、それ以外は未測定。**

## 変更範囲

- `hawkeye/cli.py` の `_write_tribunal_report` — ファイル名にティッカーを含める。
  併せて、万一同名が既にあった場合に**黙って上書きしない**ようにする（連番を
  足すか、エラーにするか。どちらにしたかと理由を証拠欄に書く）。
- `tests/` — 上記の単体テスト。特に「同じ秒に2件保存しても両方残る」ことと、
  「既存ファイルを上書きしない」ことを別々に検証する。

## 禁止事項

- **レポートの中身（`render_recommendation_ja` の出力）を変えない。** 壊れて
  いるのは保存先の名前だけであり、文書の内容は正しい。
- **走査CSV（`scan-<id>.csv`）の命名に触らない。** それは T-019 の範囲。
- **既存の保存済みレポートをリネーム・移動・削除しない。** 過去のファイルは
  そのまま残す。
- **保存先ディレクトリ（`reports_dir()`）を変えない。**
- **仕様が不明な点を推測で埋めない。**

### 実装

保存先の名前を組み立てる処理（`hawkeye/cli.py` の `_write_tribunal_report`）を
2点変えた。

1. **名前に銘柄コードを入れた。** `260819-005206-tribunal-report.md` →
   `260819-005206-RNW-tribunal-report.md`。
2. **既存ファイルを開いて書くことを、そもそも不可能にした。** 書き込みを
   `open(..., "x")`（名前が空いているときだけ作成し、埋まっていれば例外）に
   変え、埋まっていたら `-2`, `-3` … と足して空きを探す。「存在するか調べて
   から書く」形にしなかったのは、調べた後・書く前に別の実行が同じ名前を取る
   隙間が空くため。

銘柄コードに、ファイル名として使えない文字が入りうる問題（停止条件の3つ目）は
**ハイフンに置換**する形で解決した（User判断 2026-08-20）。銘柄コードは決算
カレンダーと決算専門サイトが返した文字列を大文字化しただけで文字種を検査して
おらず、`BF/B` のような表記が来ると保存が例外で落ちて**審理の結論がディスクに
1件も残らない**。置換なら文書は必ず残る。ドット（`BRK.A`）はファイル名として
合法なのでそのまま残す（`_ticker_slug` / `_UNSAFE_IN_FILENAME`）。

**衝突時に連番を足す方を選び、エラーにはしなかった理由**: エラーにすると、
守ろうとしている当のもの（その回の審理が残す唯一の文書）が失われる。連番なら
両方残り、どちらが先かはファイル名の秒とタイムスタンプで分かる。

範囲外だったが直したもの: session mode の手順書
（`.claude/skills/hawkeye-run/SKILL.md`）が旧い名前を明記していたので更新した。
これを放置すると手順書が実際と食い違う。
