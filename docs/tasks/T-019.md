# T-019: 走査CSVのファイル名を日付＋走査番号の形式に変更する

## メタデータ

- 作成日: 2026-08-19
- 更新日: 2026-08-20
- 状態: 完了
- 進捗: 100%
- 依存: 無し

## 目的

### このファイルが最終的に何のためにあるか

`hawkeye report scan` が書き出す全銘柄の表である。**Userが「今日の走査は本当に
正しく動いていたか」を自分の目と表計算ソフトで確かめるための全量データ**であり、
画面の表が省く銘柄と列を含む唯一の記録である（詳細は T-018 の目的欄）。

### 何が不便か

現在のファイル名は走査番号だけである（`hawkeye/cli.py:1170`）。

```python
path = (pathlib.Path(args.csv) if args.csv
        else reports_dir() / f"scan-{scan['id']}.csv")
```

結果として `var/reports/` にはこう並ぶ。

```
scan-1.csv
scan-2.csv
scan-3.csv
```

**いつの走査なのかがファイル名から分からない。** 走査番号は台帳の連番であって
日付ではないため、`scan-2.csv` が昨日のものか先月のものかは開くまで分からない。
数が増えるほど、目的のファイルを探すのに毎回開いて確かめることになる。

さらに `scan-` という接頭辞は、`var/reports/` に他の種類のファイル（審理レポート
など）が混在したときに、これが何のファイルなのかを説明しない。

### 放置した場合に困ること

金銭判断には効かない。**効くのはUserがこのファイルを探して開けるかどうか**で、
探せなければ検算そのものが行われなくなる。走査の妥当性をUserが自分で確かめる
経路は、この仕組みで唯一の外部監査であり、使われなくなること自体が損失である。

## 変更範囲

- `hawkeye/cli.py` の `cmd_report_scan`（1170行付近）— 既定のファイル名を
  `YYYY-MM-DD-SS-hawkeye-earnings-research.csv` の形式にする。
  - `YYYY-MM-DD` は**その走査を実行した日付**であり、レポートを出力した日付では
    ない。`hawkeye report scan --scan-id 3` を後日実行しても同じ名前になること。
  - `SS` は**走査番号（台帳の連番）**である（User決定、2026-08-19）。
    ゼロ詰めの桁数（`03` か `3` か）は実装時に決め、理由を証拠欄に書く。
  - 例: `2026-08-19-03-hawkeye-earnings-research.csv`
  - `--csv` で明示的にパスを指定したときは、従来どおりその指定を優先する。
- `tests/` — 上記の単体テスト。

## 禁止事項

- **CSVの中身（列・行・値・文字コード）を一切変えない。** このタスクは
  ファイル名だけを変える。列の追加は T-018 の範囲。
- **審理レポートのファイル名に触らない。** それは T-017 の範囲。
- **既存の `scan-1.csv` 〜 `scan-3.csv` をリネーム・移動・削除しない。**
  過去のファイルはそのまま残す。
- **保存先ディレクトリ（`reports_dir()`）を変えない。**
- **`--csv` の挙動を変えない。**
- **仕様が不明な点を推測で埋めない。**

## 完了条件

① `hawkeye report scan` を実行したとき、画面末尾の「全銘柄の表をCSVに保存
   しました: ...」が新形式のパスを表示し、そのファイルが実在することを、
   コマンド出力と `ls` の出力で示す
② `hawkeye report scan --scan-id 3` を**別の日に**実行しても、ファイル名の
   日付部分が走査を実行した日（2026-08-19）のままであることを実出力で示す。
   別の日に実行できない場合は、走査日を固定値で注入した単体テストで代替し、
   その旨を証拠欄に明記する
③ `hawkeye report scan --csv <任意のパス>` が、従来どおり指定したパスに書く
   ことを実出力で示す
④ 生成されたファイルの中身が、着手前に同じ走査番号で生成したCSVと**完全に

⑤ `.venv\Scripts\python.exe -m pytest -q` が全件成功する（着手前の件数＋新規分）

  走査日は固定値を注入し、実時間に依存させない。`--csv` 指定時に組み立てが

## 停止条件

- `CLAUDE.md` の共通停止条件。
- 台帳の走査記録に「その走査を実行した日付」が保存されていないことが分かった
  場合。その場合は日付をどこから取るかの仕様が未確定なので、着手前にUserへ
  確認する。
- 既存の保存済みCSVを参照している処理が見つかり、命名変更でそれが壊れる場合。

### 実装

既定のファイル名を組み立てる処理を新設し（`hawkeye/cli.py` の
`_scan_csv_name`）、走査レポートを書き出すコマンド（`cmd_report_scan`）が
`--csv` 未指定のときだけそれを使うようにした。

```
var/reports/scan-3.csv
  → var/reports/2026-08-19-03-hawkeye-earnings-research.csv
```

日付は**台帳の走査記録が持つ実行時刻**（`scans` テーブルの `ts` 列。JSTの
オフセット付きで保存されている）の日付部分から取る。出力した日ではないので、
後日 `--scan-id 3` を出し直しても名前は変わらない。

**着手前チェック（停止条件2つ目）**: 走査の実行日が台帳に保存されているかを
先に確認した。`scans` テーブルの `ts` 列に
`2026-08-19T00:24:22.068839+09:00` の形で入っており、仕様は未確定ではなかった
ので着手した。

**走査番号のゼロ詰めは2桁**（`03`）にした。理由: 同じ日に2回以上走査した場合、
ファイル名の並び順が走査した順序と一致する（`3` のままだと `10` が `3` より
前に来る）。100回目以降は3桁に自然に広がるだけで、切り捨ては起きない。
User決定の例（`2026-08-19-03-...`）とも一致する。

範囲外だが直したもの: session mode の手順書
（`.claude/skills/hawkeye-run/SKILL.md`）と `--csv` のヘルプ文が旧い名前を
明記していたので更新した。
