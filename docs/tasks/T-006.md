## タスク詳細

**目的**: 銘柄を指定して審理用の案件を作るコマンド（`hawkeye case open TICKER --from-earnings`）が、走査で読み取り済みの「会社の来期見通し（ガイダンス）」と「決算の理由」を審理3役への資料に載せず、`Guidance not disclosed [guidance_not_published]` / `no explanation ... (it has not been read yet)` と書いている。原因は、この経路が銘柄マスタに保存済みの最新決算行を使わず、決算カレンダーからその場で取り直して新しい行を組み立てるため（`judge_ticker`）。読み取り結果自体は保存されており採点（`hawkeye rank`）には正しく反映されているので、壊れているのは資料を書き出す経路のみ。放置すると、3役は会社が自ら見通しを引き上げた事実を知らないまま審理し、点数を付けた根拠が審理の資料からだけ消えた状態でUserがBUY/見送りの判断を受け取る（金銭判断に直接影響）。2026-08-17実測: 開いた3案件すべてで発生（ガイダンス欄の誤りはHLIT・SDRLの2件、理由欄の誤りは3件全部）。**変更範囲**: `hawkeye/scout/single.py`（`judge_ticker`: 保存済みのactive print rowを優先して使う）／`hawkeye/cli.py`（`_judged_earnings` / `cmd_case_open` の呼び出し側）／対応するテスト。**ユーザー決定（2026-08-17）**: 保存済みの読み取りと取り直した決算数値が食い違った場合は、案件を開かずに停止して人間に報告する（自動でどちらかを採らない）。**ユーザー決定（2026-08-17 着手時）**: 「食い違い」の判定は既存の同一決算判定関数（`hawkeye/scout/revision.py` の `reports_the_same_figures`: 会計四半期・発表日・ベンダー・EPS実績・売上実績の5点比較）を流用する — 読み取りを保存行に取り付ける既存経路と同じ基準に揃える。**禁止事項**: T-005で入れた走査→審理の経路（`hawkeye rank` 後の説明文再生成）は触らない。`record_print` / `revise_print` の実績値訂正の仕組みと既存データの扱いは変えない。`hawkeye/tribunal/prompts.py` の役割プロンプトは触らない。今日開いた3案件（case_5944e2300f48 HLIT / case_95864f27c41b AMBQ / case_af22b31960b6 SDRL）は修正の検証材料として残し、削除しない。
