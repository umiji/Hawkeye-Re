# 発見と振り返り — 索引

セッションを超えて効く知識だけを置きます。**分類の軸は話題ではなく「いつ読むか」**です。
読む契機で分けないと、必要な1枚が長大な1ファイルの中に埋もれて、結局誰も読みません。

| いつ読むか | ファイル | 中身 |
|---|---|---|
| **何かを提案する前**(「こうしたらどうか」と言いかけたら必ず) | [REJECTED.ja.md](REJECTED.ja.md) | 検討して**棄却済み**の案と、その理由 |
| **数字を引用する前**(「25%」「2%」などを根拠に使うとき) | [MEASUREMENTS.ja.md](MEASUREMENTS.ja.md) | 実測値。母集団・日付・測り方つき |
| **コマンドやツールで詰まったとき** | [TOOLING.ja.md](TOOLING.ja.md) | 環境の落とし穴と回避策 |
| **セッションの終わり、または進め方に迷ったとき** | [RETROSPECTIVES.ja.md](RETROSPECTIVES.ja.md) | 開発プロセスの振り返り |

## 他の文書との分担

| 文書 | 何を書くか | 寿命 |
|---|---|---|
| `CLAUDE.md` の引き継ぎログ | **そのセッションで何が起きたか** | 次のセッションまで |
| `docs/design/` | **設計と現状**(To-Be、As-Is、ギャップ表、データモデル) | 設計が変わるまで |
| **この `docs/findings/`** | **信念が覆った実測・棄却案・プロセスの反省** | 恒久 |

## 書くときの約束

1. **実測には日付と母集団を付ける。** 「食い違いは25%」ではなく「2026-08-02、決算
   カレンダー731銘柄から14件ごとに抜き取った50銘柄で12/48」。数字だけが残ると、
   後から「どの母集団の話か」が分からなくなり、再利用も反証もできません。
2. **設計文書に落ちた内容は複製しない。** 結論が `docs/design/` に入ったら、ここには
   1行の見出しと参照先だけを残します。2箇所に同じ説明があると必ず片方が古くなります。
3. **棄却した案は、棄却理由と一緒に書く。** 理由の無い「不採用」は、次のセッションが
   同じ案を良いアイデアとして再発見します。
4. **1ファイルが長くなったら、読む契機で割る。** 話題で割らないこと——同じ話題でも
   「提案前に読む」ものと「詰まったときに読む」ものは別の紙にすべきです。
