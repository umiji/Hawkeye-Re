## 句読点前の空白を直すのに必要な文字は6字だけだった(2026-08-18実測 / T-012)

**測る理由**: 上の欠陥を直すには「発表文のどの記号の直前から空白を落とすか」を
決める必要がある。この工程が作るテキストは、審理3役が読む抜粋の切り出し元であり、
かつ3役の引用が本物かを照合する基準そのものなので、**必要以上に1文字でも書き換えれば
会社の書いた文を我々が改変したことになる。**

**「空白＋記号」の大半は正常である。** 実発表文10本での出現数:

| 記号 | 空白が直前にある回数 | 直して良いか |
| --- | --- | --- |
| `(` | 734 | ✗ 英語として正常（`EBITDA (non-GAAP)`） |
| `$` | 726 | ✗ 正常 |
| `)` | 287 | △ 効果ゼロ（後述） |
| `,` | 231 | ○ |
| `—` | 108 | ✗ 正常（`revenue — up 13%`） |
| `"` | 100 | ✗ 開き引用符と区別できない |
| `.` | 94 | ○ |
| `%` | 53 | ✗ **誤修正あり**（後述） |
| `:` | 8 | ○ |

**候補を4段階で試し、最小の集合で13件全部が復活した**（T-011で却下された13ブロックを
そのまま使い、修正後の発表文と突き合わせた）:

| 対象文字 | 却下13件の復活 | 発表文への改変箇所 |
| --- | --- | --- |
| **`, . ; : ! ?`** | **13 / 13** | **173** |
| ＋ `) ] }` | 13 / 13 | 365 |
| ＋ `%` | 13 / 13 | 396 |
| ＋ `”` | 13 / 13 | 396 |

**広げても復活は1件も増えず、改変箇所だけが2〜3倍になる。** そして広げた側には
実在の誤修正がある:

```
%  を含めると: 表の見出し  '2025 \xa0 \xa0 % Change' → '2025% Change'（年号と見出し語が接着）
’  を含めると: 2027年度の略記 'fiscal ’27'    → 'fiscal’27'
)  を含めると: 'SDRL の '( www.seadrill.com )' → '( www.seadrill.com)'（非対称になり、
   読み手は自然形 '(www.seadrill.com)' に直すため結局一致しない）
```

**6字が安全なのは、英語がこの6字の直前に空白を置かないからである。** 改行は対象外
（`[^\S\n]`）—— 6字はいずれも改行直後には1件も出現せず、含めても得るものが無い一方、
表の行を接着する危険だけが残る。

**修正後の実測（同一30銘柄、本番コード経路、2026-08-18）**:

| 測ったもの | 修正前(T-011) | **修正後(T-012)** |
| --- | --- | --- |
| 抜粋を作れた | 28 / 30 | **29 / 30** |
| 返ってきたブロック | 161 | 160 |
| 原文照合に落ちたブロック | 13 / 161 = 8.1% | **0 / 160 = 0%** |
| `extractor_invented_every_block` と記録された銘柄 | 1(SDRL、実際は誤警報) | **0** |
| 抜粋の総文字数 | 29,920(発表文の4.1%) | 32,721(発表文の4.4%) |

抜粋を作れなかった1件は DFDV で、理由は `no_cause_in_release`（発表文に理由が
書かれていない）—— 2.5 Flash・3.5 Flash Lite の両方で一貫して同じ答えであり、
これは会社についての事実であって欠陥ではない。

実発表文10本で「6字の直前に残った空白」は**全本0件**。同時に `fiscal ’27` /
`% Change` / `( www.seadrill.com )` / `(BUSINESS WIRE)` はいずれも無傷。

**留保**:
- 却下0件は標本30銘柄・166ブロックでの結果であり、**抜き出し役が書き換えないことの
  証明ではない**。書き換えを捕まえる機構（`build_cause_text` の逐語照合）は1文字も
  緩めていないので、AII型の改変が起きれば従来どおり検出される（T-013以降は却下では
  なく「改変」として計上され、抜粋には原文の文字が入る）。
- 抜き出し役の出力は**非決定的**である。修正前の SDRL を2026-08-18に再実行したところ、
  T-011測定時の `extractor_invented_every_block` ではなく抜粋の生成に成功した
  （モデルが空白ごと写したため照合を通った）。**つまりこの欠陥は「却下される」形の
  ほかに「空白付きの抜粋がそのまま審理3役に渡る」形でも現れており、後者のほうが
  静かで見つけにくい。** T-012の完了判定は、再現性のある後者（抜粋に空白が残るか）
  で行った。
- 修正は今後の実行が作るテキストだけを変える。台帳に記録済みの抜粋は当時の文字列の
  まま残る（invariant 1）。同じ発表文を今読み直すと文字数が数十字減る
  （例: SDRL 25,867 → 25,825）。

### HTTP 500 は「散発的」ではなく、銘柄ごとに決まっている(2026-08-08 訂正)

|---|---|---|
| 大型株50銘柄(単体スクリプト) | 49 | **1**(GOOG) |

## EarningsWhispers のサマリ文と実績の安定性(2026-08-06)

**方法**: 2026-08-05に採取したfixture 10銘柄を翌日(8/6)に引き直し、
`summary` 文字列と実績を突き合わせた。標本10件。

| 結果 | 件数 | 意味 |
|---|---|---|
| 同じ決算・サマリが**完全一致** | 5 (ACAD/ADM/AME/AMD/ALAB) | 確定した決算のサマリは**書き換えられない**。文中の「現在のコンセンサス」は発表直後の値のまま凍る |
| 同じ決算・サマリが**変化** | **1 (ADEA)** | **実績EPSが $0.34 → $0.42 に改訂された**(売上は不変)。下記 |
| 別の決算に入れ替わった | 4 (ACA/ADMA/ADNT/ALB) | 8/5採取時は前期のままだったが、**8/6には8/5発表分に更新されていた** |

### 1. サマリ内の「現在のコンセンサス」は使える

サマリはEWが発表直後(DUOLなら16:02 ET、リリースの数分後)に書き、以後
書き換えない。したがって文中の "The current consensus ... estimate is ... for the
quarter ending ..." は**アナリストがガイダンスに反応して修正する前の値**であり、
ガイダンスの物差しとして汚染されていない。**Yahooを翌四半期コンセンサスのために
残す必要は無い**(2026-08-06に一度そう提案したが、この測定で撤回)。

同じ47銘柄のfixtureでの出現率:

| 項目 | 件数 |
|---|---|
| サマリに「現在のコンセンサス」の記述がある | 25/47 |
| うち**翌四半期**の物差し(EPS 2・売上 10) | 12 |
| うち**通期**の物差し(EPS 2・売上 15) | 17 |
| ガイダンスを載せている銘柄 | 20 |
| **↑のうち翌四半期の物差しも同じサマリにある** | **11/20** |

売上の対(売上ガイダンス×売上コンセンサス)が主流で、EPSは少ない。通期の物差しが
17件あるので、いま `guidance_period_not_comparable` で捨てている通期ガイダンスも
期間を揃えて比較できる余地がある。

### 2. EWは実績を後から改訂することがある(新発見・要対処)

ADEAは同じ決算(2026-08-05発表、2026-Q2)のまま、**実績EPSだけが翌日に
$0.34 → $0.42 (+24%) に変わった**。売上は $96.12M で不変。標本10件中1件だが、
影響は大きい:

- 決算行は**追記のみで書き換えられない**設計なので、早く読んだ $0.34 を記録すると
  その行自体は直せない
  → **【2026-08-07 対応済み】** 改訂は「新しい行を有効（`active`）で追加し、古い行を
  無効（`superseded`）に落として残す」形で書けるようになった
  （`StockStore.revise_print`）。$0.34 の行が残るのは意図で、順位を付けた時点で
  どの値を見ていたかを消さないため。**ただし改訂を検出してユーザーに差分を見せる
  処理（タスク8.5）はまだ無い**ので、走査は改訂を拾わない
- サプライズ比が丸ごと変わる。$0.34 と $0.42 では上振れ・下振れが反転しうる
- **48時間の保留は「実績が届くまで待つ」規則であって「実績が動かなくなるまで
  待つ」規則ではない。** 届いた直後に読むほどこの改訂を踏みやすい

未測定: 改訂の発生率(標本10件では 1/6 = 17%だが、確定済み決算6件のうち1件という
極めて小さい標本)、改訂が起きる時間帯、改訂の向き。

### 3. 48時間の保留は足りている(暫定)

8/5採取時に前期のままだった4銘柄は、**4件とも翌日には当期に更新されていた**。
「EWの実績反映は約1日遅れ」(2026-08-05測定、16/16件)と整合する。48時間で
足りない事例はまだ観測されていない。ただしIPO直後銘柄(SPCX)は未測定。

## ガイダンス(会社が出す業績見通し)をコードでどこまで読めるか(2026-08-10)

**母集団**: 決算専門サイト EarningsWhispers の応答を記録した47銘柄
（`tests/fixtures/whispers/`・2026-08-05採取。**無作為標本ではない** — アルファベット順の
先頭付近に偏っています）。数えたのは「要約文（`summary`）の中で、会社自身が将来について
述べている文」です。

| 項目 | 修正前 | 修正後 |
| --- | --- | --- |
| 会社が将来について何か述べている | 25/47 | 25/47 |
| **コードが数字のレンジを読み取れた** | **20** | **23** |
| 文は見つけたが数字を取れなかった | 1 | 2 |
| **文そのものを認識できなかった** | **4** | **0** |

修正の中身は書き出しの言い回し2つ（`continues to expect` / 前置きを挟む
`said, ... , it now expects`）を足しただけです。ADEA・ADV・AHCO・ALB の4件は、
通期の売上レンジを普通の数字で書いているのに「ガイダンス開示なし」として記録されて
いました。

**残る2件は、LLMに読ませても読めません。** 文中に比較可能な数字が存在しないためです:

- **ADV**: `2026 revenue of $3.54 billion to $2.67 billion` — 上限が下限より小さい。
  提供元の打ち間違い。中央値を取ると $3.10 billion という誰も公表していない数字が出る
  → `range_inverted` として拒否
- **ALGT**: `third quarter results to range from a loss of $1.00 per share to breakeven`
  と `2026 earnings of more than $6.00 per share` — 一方は非数値、もう一方は上限が無い

**⚠️ この表から「LLMに読ませても0件」と結論したのは誤りでした（2026-08-10 訂正）。**
残る2件は、どちらもLLMなら読めます:

- **ADV** `$3.54 billion to $2.67 billion` — 打ち間違いではなく、**上限を先に書いた
  だけ**。順序が入れ替わっただけの範囲で、コード側でそれを打ち間違いと判別する手段は
  ありません（「打ち間違い」という読みは私の憶測でした）
- **ALGT** `a loss of $1.00 per share to breakeven` — **-1.00〜0.00**。
  言葉の意味が分かる読み手なら普通に読めます

さらに本質的な点として、**この表の「読めた23件」という数字自体が誤解を招きます**。
パターンが読めるのは、パターンを書いたときに見た形の文だけです。標本を増やせば
「読めた件数」は増え続け、同時に「読めない形」も出続けます。件数で測る限り
成功に見え続ける、という性質があります。

→ **2026-08-10以降、ガイダンスはエージェント（AI）が全部読みます**
（`hawkeye/scout/guidance_agent.py`）。コード側の読み取りは関数ごと削除しました。
**アナリスト予想の文は今もコードで読みます** — 提供元が数値から機械生成している文
なので形が1つしか無く、パターンが正しく効く唯一のケースだからです。

## 外れたブロックを救う閾値と、その分け方(2026-08-18 / T-013)

**測った理由**: 決算発表文から理由を抜き出す工程で、厳密一致に外れたブロックを

| 母集団 | 件数 | 最大 | p99 | 中央値 |
|---|---|---|---|---|
| **別会社**の発表文に対する類似度 | 356組 | **0.7018** | 0.5792 | 0.3333 |
| **同じ発表文の別の箇所**(本来の箇所を隠して再照合) | 86件 | **0.8951** | — | 0.4858 |
| T-012で却下されていた13ブロック(救うべき本物) | 13件 | 0.9986 | — | 最小 **0.9932** |

窓は **(0.8951, 0.9932]**、採用値 **0.95**(両側に約4ポイントの余裕)。
懸念していた「ALCOの3か月 vs 9か月」の取り違えは **0.7636** 止まりだった。
同一文が発表文に2回出てくる例は3件あったが、切り出す文字が同じなので実害は無い。

### 類似度では「こちらの不具合」と「モデルの改変」を分けられない

| ブロック | 類似度 | 差分の中身 |
|---|---|---|
| T-012の13件(救うべき) | 0.9932〜0.9986 | **全件、空白の削除のみ**(英数字の差 0件) |

**AIIは救うべき3件より上に来る。** どこに閾値を引いても分離できない。そこで
**差分に英数字が1文字でも含まれるか**で分けることにした。これは実測で完全に分離する
(13件すべて「英数字の差なし」、AIIのみ「あり」)。両方とも救済し(抜粋には発表文の
文字が入るので中身は常に正しい)、**別々に数えて表示する**。

## 救済が本番で初めて働いた回と、その中身(2026-08-18 / T-013の未検証項目の検証)

**方法**: 本番の台帳に触れないよう使い捨ての `HAWKEYE_VAR` の下で、実運用と同じ
`hawkeye scout --days 10`(走査期間 2026-08-08〜08-17) → `hawkeye rank` →
`hawkeye report scan` を1回通した。標本は入口ゲートまで到達した31銘柄のうち、
発表文を読めた **29銘柄・161ブロック**。

- **入口ゲート通過 15件**。走査レポート §② の銘柄ごとの抜粋行が、実在のゲート通過銘柄
  (AMBQ / HLIT / MSGE)で表示されることをここで初めて確認した。
- **救済の内訳: 採用160 / 修正0 / 改変1 / 却下0。** CSV 143行の4列合計と §⑤ の表示は
  完全に一致。
- **改変1件は BSP**。抜き出し役が送った文と発表文の違いは、脚注番号の「4」1文字だけ:

  ```
  抜き出し役: Organic revenue growth was 3% in Q2 2026, ...
  発表文    : Organic revenue growth 4 was 3% in Q2 2026, ...
  ```

**この1件の解釈(重要)**: これは抜き出し役の非ではない。BSPの発表文は末尾に
`______________________` の区切りと `4 "Organic revenue growth" for a given period is
defined as ...` という脚注定義を持つ本文であり、HTMLを文章に直す処理
(`hawkeye/marketdata/whispers.py` の `release_text`)が上付き文字の脚注番号を文中に
そのまま落として `growth 4 was 3%` を作っていた。**T-012と同じ「こちらの変換ミス」の
系統でありながら「改変」に計上されている** —— T-013が分けると決めた2種類の区別が逆向きに
崩れる形。抜粋の中身は原文の文字なので安全だが、数え方は正しくない。

**脚注番号の混入率**: 脚注定義ブロック(`_____` の区切り + `N ...` の定義行)の存在を
条件にした厳しめの数え方で、**29銘柄中1銘柄・161ブロック中1件**。
`[a-z] N [a-z]` だけの緩い正規表現では17銘柄が該当したが、これは
`an increase of 11 percentage points` のような正常な文も拾うため**上限であって実測ではない**。

**留保**:
- 標本は1回・1日分の走査であり、脚注番号を上付きで打つ企業の割合を測ったものではない。
- 「修正」(こちらの変換ミスを直して採用)は依然として本番実例 **0件**。T-012が発生源を
  消しているため、上記(a)のような同系統の事象が起きても「改変」側に入ってしまう。
