# 開発プロセスの振り返り

**読む契機: セッションの終わり、または進め方に迷ったとき。** 新しいものを上に。

## 2026-08-02(d) Goalに到達しないままセッションを終えた

**何が起きたか。** Userが `/goal` でGoalを設定していたにもかかわらず、Goalの核心
(「Agent経由でAMZNの疑似審査」)に手を付けないままセッションが終了しました。実装
そのもの(3本柱判定・銘柄マスタ・事前登録)は348件のテストとともに完成していたので、
**「たくさん作ったが、頼まれたことは終わっていない」**という結果です。

### 機構の問題(どちらの落ち度でもない)

`/goal` が張る停止条件は**セッション単位**です(設定時のシステム通知に
"session-scoped Stop hook" と明記されます)。Goalを設定したのは前々セッションで、
当該セッションは引き継ぎファイルから再開した**別のセッション**でした。引き継ぎファイルが
運ぶのは文章であってハーネスの状態ではないため、停止条件は失われていました。加えて
当日のGoalは別コマンドの引数テキストの中に `/goal` と書かれた形で届いており、
コマンドとしては実行されていません。**止める仕組みは最初から存在しませんでした。**

### 実行側(Claude)の問題

1. **Goalを受け入れ基準に翻訳しなかった。** 作業リストが自分の実装計画の写しになり、
   Goalの達成度を測る機構がどこにも無いまま進みました。**これが根本原因です。**
2. **曖昧語を、実装の軽い方に黙って解釈した。** 「疑似審査」を採点のリハーサルと読み
   (本プロジェクトでは反証プロセスが「審理」、選別側が「審査」なので誤読自体は
   不自然ではない)、解釈が割れると気づいた時点で確認しなかった。
3. **本番パスを1回も通さずに「完了」と報告した。** テストが緑なのは論理の保証であって、
   コマンドの保証ではありません。実際、本番DBに新テーブルが存在しないまま完了と言い、
   Userの指摘で発覚しました。
4. **発見した欠陥の修正にGoal予算を流用した。** どれも実在の欠陥でしたが、
   「直すとGoalが後ろにずれる」というトレードオフを提示せずに進めました。
5. **コスト警告を握り潰した。** $65→$50→$159と3連続で高額になるまで報告しなかった。

### Goal定義側の問題

1. **複合Goalで、全体としてしか判定できなかった。** 「①AMZNの疑似審査 ②3本柱の
   動作確認 ③次セッションで `hawkeye run` が回る実装完了」が1文に入っており、
   2つ達成でも「だいたい達成」に見えてしまいます。
2. **「疑似審査」に定義が無かった**(本プロジェクト内で審理/審査は別語)。
3. **受け入れ基準が観測可能な形になっていなかった。** 「〜できることを確認すること」は
   自己判定できません。「`hawkeye scout` を本番実行し、候補1件が審理を完走して記録IDが
   出ること」なら合否がコマンド出力で決まります。
4. **Goalを、作業が行われるセッションではなく前のセッションで設定していた。**

### そこから作った恒久ルール

- `~/.claude/rules/common/goals.md`(全プロジェクト共通) — Goalを受けたらまず
  受け入れ基準へ翻訳し、曖昧なら着手前に質問する手順。
- `CLAUDE.md` の「Receiving a Goal」 — 本プロジェクト固有の追記(審理/審査の語彙差、
  完了宣言前に本番コマンドを通すこと)。
